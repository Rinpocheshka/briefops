# Интеграционный API и n8n

BriefOps принимает обращения через HTTP API. n8n может передавать события из формы, почты, мессенджера или другой системы и запускать проверку времени ответа. Основная обработка выполняется сервисом BriefOps; n8n запускается отдельно.

## Авторизация

Интеграционные запросы требуют заголовок:

```text
Authorization: Bearer <BRIEFOPS_AUTOMATION_TOKEN>
Content-Type: application/json
```

Используйте отдельный токен, настроенный у владельца развёртывания. Ключ NVIDIA в n8n не передаётся. В локальной среде автоматически созданный токен доступен командой `python app.py --print-token`.

## Принять обращение

`POST /api/automation/intake`

```json
{
  "source": "n8n",
  "message_id": "source-event-123",
  "name": "Алина",
  "company": "Mellow Studio",
  "text": "Нужна автоматизация заявок. Бюджет 160 тыс. рублей. Контакт alina@example.com."
}
```

Обязательное поле — `text` (8–10 000 символов). Источник: `website`, `email`, `telegram`, `manual` или `n8n`. Передавайте стабильный `message_id` из исходной системы либо заголовок `Idempotency-Key`.

- `202`: обращение сохранено и поставлено в очередь.
- `200`, `replayed: true`: это событие уже принято, возвращена существующая заявка.
- `409`: тот же ID использован с другим содержимым.

Ответ содержит `lead.id`, по которому можно отслеживать обработку. Worker забирает заявку автоматически.

## Дополнительные методы

| Метод | Запрос | Результат |
| --- | --- | --- |
| Запустить обработку | `POST /api/automation/process`, `{ "id": "LEAD_ID" }` | Текущая карточка после попытки обработки |
| Проверить время ответа | `POST /api/automation/sweep`, `{}` | Количество созданных задач |
| Состояние сервиса | `GET /api/health` | Доступность сервиса и хранилища |

При занятом worker или назначенном retry обработка может оставаться незавершённой. Учитывайте состояние `lead.status`, а не только HTTP-код вызова process.

## Готовые процессы n8n

- `workflows/intake.json`: Webhook → сохранение → обработка → проверка повтора → ответ источнику.
- `workflows/sla.json`: Schedule Trigger каждые пять минут → проверка времени ответа.

1. Скачайте файлы с экрана «Как это работает» → «Подключить свой источник». Публичная версия экспортов уже содержит адрес облачного API. В репозитории экспорты направлены на localhost.
2. В n8n выберите **Import from File** для каждого процесса.
3. Создайте credential **Header Auth**: Name — `Authorization`, Value — `Bearer <TOKEN>`.
4. Выберите credential в Webhook и HTTP Request узлах. Экспорты не содержат ключей или ID credentials.
5. Нажмите **Listen for test event**, передайте JSON из `examples/inquiry.json` с токеном, проверьте карточку BriefOps.
6. Повторите событие с тем же ID: новой сделки быть не должно. Затем опубликуйте workflow и используйте его Production URL.

HTTP-контракт проверен интеграционными тестами и на облачном сервисе. Выполнение экспортов непосредственно внутри движка n8n не входит в текущую проверку релиза.
