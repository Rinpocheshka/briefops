# Проверка качества BriefOps

## Автоматические проверки

```bash
npm ci
npm run build
python -m unittest discover -s tests -v
```

Сборка проверяет TypeScript-конфигурацию Neon, синтаксис JavaScript и Python, JSON процессов и наличие статических файлов. Unit и HTTP-тесты используют изолированные временные базы.

| Область | Проверяемое поведение |
| --- | --- |
| Приём | Сохранение до обработки, конфликт ID, одновременная доставка одного события |
| Разбор | Контакты и бюджет из текста, тип услуги, неполные данные, JSON-контракт AI |
| Повторы | Точные межканальные повторы, похожие новые задачи, анонимные обращения |
| Очередь | Retry, ручной повтор, ограничение попыток, восстановление и активный lease |
| Согласование | Валидация полей, обновление сделки, идемпотентное сохранение outbox |
| Контроль ответа | Одна задача на просрочку, закрытие задач при согласовании |
| HTTP | Токен API, HTTPS Origin, CSRF, Host, квоты и безопасный экспорт |
| AI | NVIDIA/OpenRouter adapters, некорректный JSON, резервные правила |
| n8n | Связи узлов, отсутствие credentials, адрес облачного API в экспортах |

## Postgres

Набор из 20 бизнес- и HTTP-сценариев выполнен на отдельной Neon-ветке `dev-briefops`. Обращения, сделки, retry, согласование и контроль времени ответа проверены на реальном Postgres. Тестовые подключения отделены от production.

## Облачный сценарий

На https://briefops.onrender.com проверены:

1. Приём обращения через защищённый API.
2. AI-разбор NVIDIA с извлечением задачи, бюджета и контакта.
3. Повтор события и конфликт другого текста с тем же ID.
4. Исправление бюджета, изменение черновика и согласование.
5. Переход сделки в этап готового ответа.
6. Сохранность карточки и изменений после restart и повторного deployment Render.
7. Отсутствие credentials в состоянии браузера и экспортах процессов.

## Интерфейс 1.1

Проверка проводится в реальном браузере на desktop и ширине 390 px:

- пробная заявка → результат обработки → изменение бюджета и текста → сохранение → согласование;
- раздел готовых ответов и следующий шаг после согласования;
- форма с одним обязательным полем и раскрываемыми дополнительными данными;
- запрет согласования без контакта и включение действия после добавления контакта;
- сохранность несохранённых полей при фоновых обновлениях;
- отдельные список и карточка на телефоне, возврат к очереди и нижняя навигация;
- исходное сообщение, история, поиск, канбан и сценарии повторов;
- отсутствие горизонтальной прокрутки и проверка видимости основных действий.

Снимки и подробные локальные результаты хранятся в artifacts/. Секреты и рабочие базы исключены из исходного архива.

## Границы проверки

Проверен API-контракт с n8n и экспорт процессов, но не их выполнение внутри движка n8n. Внешняя CRM не подключена. Email в закрытой рабочей области описан в WEBSITE_EMAIL.md. Публичный стенд использует общие вымышленные данные и не предназначен для хранения реальных обращений без отдельной настройки доступа.

## Результат выпуска 1.1

`npm run build` — обе проверки BUILD OK. Регрессия — 36 тестов, OK. Ручная проверка выполнена на desktop и 390 px: пробный сценарий, редактирование бюджета и ответа, согласование, готовые ответы, форма без контакта, добавление контакта, сохранность правок при обновлении и мобильный возврат к списку. Горизонтальная прокрутка не обнаружена.


## Выпуск 1.2

Дополнительные проверки: изоляция рабочей базы от публичных API и CSV, подтверждённый владелец в JWT, запрет обычных писем и чужих форм, структурированный контакт, отсутствие отправки при согласовании, единственная отправка при конкурентных нажатиях, постоянный ID при сетевом повторе и остановка при неопределённом результате. Скрипт Google отдельно проверяется на подпись, возраст запроса, одного получателя и постоянную защиту от повторов. Интеграционный тест Neon использует выделенную ветку и тестовый почтовый адаптер.
