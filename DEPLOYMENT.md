# Развёртывание BriefOps

## Состав

Render запускает Python web service. Neon хранит обращения, задания, сделки, задачи, историю и согласованные ответы. NVIDIA вызывается сервером. n8n — отдельный интеграционный сервис.

## Локальная среда

Установите Python-зависимости из `requirements.txt`. `run.ps1` использует `.venv`, если оно создано. Переменные загружаются с приоритетом: окружение процесса → `.env.local` → `.env`. При отсутствии `DATABASE_URL` используется SQLite в `data/`.

```bash
python app.py                 # запуск
python app.py --rules         # без вызовов AI
python app.py --empty         # без начального набора данных
python app.py --port 8788     # другой порт
```

`--empty` и `--db` не меняют выбранный Postgres: подключение определяется `DATABASE_URL`.

## Переменные среды

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Pooled TLS-подключение приложения к Postgres |
| `DATABASE_URL_UNPOOLED` | Прямое TLS-подключение для инициализации схемы |
| `BRIEFOPS_LLM_PROVIDER` | `nvidia` или `openrouter` |
| `NVIDIA_API_KEY`, `NVIDIA_MODEL` | Ключ и модель NVIDIA |
| `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` | Альтернативный провайдер |
| `BRIEFOPS_AUTOMATION_TOKEN` | Bearer-токен интеграционного API |
| `BRIEFOPS_PUBLIC_DEMO` | `1` включает сохраняемые дневные квоты |
| `BRIEFOPS_LLM_DAILY_LIMIT` | Суточная квота AI; стандартное значение 50 |
| `BRIEFOPS_WRITE_DAILY_LIMIT` | Суточная квота изменений; стандартное значение 300 |
| `PORT` | HTTP-порт, предоставленный платформой |
| `BRIEFOPS_ALLOWED_HOSTS` | Дополнительные разрешённые имена хостов через запятую |
| `BRIEFOPS_PUBLIC_ORIGIN` | Фиксированный допустимый Origin для изменений из браузера |

Локальные секреты и runtime-данные исключены из Git. Секреты облачного сервиса хранятся в Render Environment или secret file `.env`. Управляющий ключ Render не требуется приложению.

## Neon

Декларация сервисов и политики новых веток находится в `neon.ts`. Приложение использует Postgres, без дополнительных Neon-сервисов. Для запросов работает клиентский пул до четырёх соединений; начальная схема создаётся через прямой endpoint. Изменения существующих таблиц следует оформлять отдельными миграциями и проверять на ветке разработки до применения.

```bash
neon deploy
```

CLI получает параметры подключения выбранной ветки в `.env.local`. Перед запуском проверки убедитесь, что выбрана нужная ветка. `tools/test_neon.py` требует отдельную ветку `dev-briefops` и очищает только её тестовые таблицы.

## Render

В `render.yaml` описаны runtime, команды запуска и health check:

```text
Build:  pip install -r requirements.txt && python tools/build.py
Start:  python -u app.py --llm
Health: /api/health
```

Сервис слушает `0.0.0.0:$PORT`. Разрешается назначенный Render hostname; изменения из браузера проверяют HTTPS Origin и CSRF-токен. Health check выполняет запрос к БД и возвращает 503 при недоступности хранилища.

Для обновления подключите GitHub deployment в Render либо используйте Render CLI:

```bash
render deploys create <SERVICE_ID> --wait --output json
```

## Эксплуатация

- Обрабатывается один экземпляр сервиса. При пересечении процессов деплоя активное задание защищено сроком обработки 120 секунд и транзакционной блокировкой.
- Квоты сохраняются в БД и считаются по суткам UTC. При исчерпании AI-квоты включаются правила; квота изменений возвращает HTTP 429.
- На бесплатном Render сервис может засыпать после простоя. Пока процесс не работает, очередь и контроль времени ответа ожидают его возобновления. Непрерывный SLA требует постоянно работающего процесса.
- Публичная среда общая и содержит тестовые данные. Для реальных клиентов необходимы отдельное окружение, аутентификация, роли, резервное копирование и мониторинг.
- Согласование записывает текст в outbox. Отправку клиенту и подтверждение доставки должен выполнять отдельный адаптер.

## Рабочая область и email

Публичное демо и рабочий кабинет могут обслуживаться одним процессом, но используют разные базы. Включение, переменные Neon Auth и почтового сервиса, ограничения доставки описаны в [WEBSITE_EMAIL.md](WEBSITE_EMAIL.md). Free Render может засыпать, поэтому для постоянного рабочего потока требуется учитывать задержку пробуждения и доступность webhook. Почтовый адаптер работает по HTTPS; SMTP-порты не используются.
