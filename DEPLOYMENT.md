# BriefOps: Render + Neon

**Публичное демо:** https://briefops.onrender.com · **Исходники:** https://github.com/Rinpocheshka/briefops

## Что размещается

Render запускает один Python web service. Neon хранит заявки, задания, сделки, черновики, журнал, согласованные ответы и дневные квоты. NVIDIA вызывается только сервером. n8n остаётся отдельной опциональной интеграцией: его движок не развёрнут этим проектом.

На Render используется бесплатный план. Это общее демо с вымышленными данными; любой посетитель видит и может изменять демонстрационные карточки. Для работы с реальными данными нужны пользователи, разграничение доступа и отдельное окружение.

## Конфигурация

- `render.yaml`: воспроизводимая конфигурация Python-сервиса, health check `/api/health`.
- `neon.ts`: существующая декларация Postgres и политики веток сохранена; дополнительные платные сервисы не включались.
- `DATABASE_URL`: pooled TLS-соединения для запросов приложения, клиентский пул до четырёх соединений.
- `DATABASE_URL_UNPOOLED`: прямое TLS-соединение для идемпотентной начальной схемы. Изменения схемы хранятся в коде Store; новое изменение схемы существующей таблицы должно получить отдельную миграцию.
- `BRIEFOPS_LLM_PROVIDER=nvidia`, `NVIDIA_MODEL`, `NVIDIA_API_KEY`: настройки AI-разбора.
- `BRIEFOPS_AUTOMATION_TOKEN`: отдельный токен для n8n/API, не выводится в браузер.
- `BRIEFOPS_PUBLIC_DEMO=1`: включает сохраняемые дневные квоты; 50 обращений к модели и 300 изменений демо в сутки UTC. При исчерпании AI-квоты работают правила; лимит записей возвращает HTTP 429.
- `RENDER_EXTERNAL_HOSTNAME`: разрешает только назначенный Render hostname. HTTPS Origin проверяется при изменении данных.

Секреты передаются в Render secret file `.env`, вне Git. Локально `.env.local` и `.env` загружаются с приоритетом переменных процесса, затем `.env.local`, затем `.env`. Выданный ключ Render нужен только для управления деплоем и в само приложение не передаётся.

SQLite сохранён для автономного запуска без `DATABASE_URL`. Исходная локальная база не удаляется и не заменяется. Новая cloud-база получает только вымышленные примеры.

## Сборка и проверки

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
npm run build
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`npm run build` проверяет TypeScript-конфигурацию Neon, синтаксис JavaScript/Python, JSON процессов и наличие статических файлов. Frontend статический: отдельного бандла React здесь нет.

Миграции и бизнес-сценарии дополнительно проверяются на ветке `dev-briefops`, созданной от production, с TTL семь дней. Подключение тестов хранится в игнорируемом `artifacts/neon-test.env`. `tools/test_neon.py` требует именно эту ветку и очищает только тестовые таблицы. Не использовать его с production-подключением.

Очередь берёт задание в обработку на 120 секунд. Перезапуск не отбирает активное задание у предыдущего процесса; по истечении срока оно доступно повторно. Короткие изменения сериализуются транзакционным advisory lock в Postgres, чтобы не создавать повторов при пересечении процессов деплоя.

## Ограничения бесплатного демо

Render может приостанавливать сервис после простоя, поэтому первое открытие бывает медленнее. Когда сервис спит, встроенная очередь и проверка SLA не выполняются до пробуждения. Для непрерывного рабочего SLA понадобится постоянно работающий процесс. Подтверждение ответа сохраняет его в outbox; реальной отправки клиентам нет.
