# Аудит BriefOps и формы World of Vibecraft

Проверка выпуска 1.3, 26 октября 2026. Область: исходный код, зависимости, HTTP API, изоляция данных, очереди, отправка email, интерфейс и тексты обоих сайтов. Это проверка приложения и опубликованных сценариев, а не независимый пентест инфраструктуры Google, Render, Neon и GitHub.

## Исправленные ошибки

| Проблема | Исправление |
| --- | --- |
| «Проверить» пропускал очередь, retry и ошибки, хотя список их показывал | Единые серверные определения списков и счётчиков; отдельные ошибки и повторы |
| Согласование скрывало неотправленный ответ и завершало контроль времени | В рабочем кабинете отдельные «Проверить», «Отправка», «Отправлено»; контроль завершается после подтверждения Google |
| Ошибка отправки не имела понятного следующего действия | Раздельные состояния очереди, отправки, отказа и неопределённого результата; ручной повтор отказа с прежним ID |
| Согласованный текст невозможно исправить до отправки | Возврат в черновик до создания отправки; после постановки письма в очередь текст и получатель фиксированы |
| Параллельные вкладки могли затереть новые правки | Проверка версии карточки перед сохранением; HTTP 409 при конфликте |
| Повтор формы расходовал суточную квоту повторно | Квота учитывается атомарно после проверки ID; неуспешная транзакция откатывает все счётчики |
| Быстрая отправка и заполненная ловушка могли показать ложный успех | Успех формы только после `accepted: true`; ловушка отклоняет запрос явно |
| Форма удаляла `$`, обратные кавычки и фрагменты кода из задания | Исходный текст сохраняется; при выводе используется экранирование |
| Ошибка сети вела к потере заполненной формы | Поля и ID сохраняются для повтора; новый текст получает новый ID; тайм-аут 90 секунд |
| Нет строгой проверки Origin и некоторых входных форматов | Обязательный разрешённый Origin, типы и длины полей, валидный контакт, UTF-8/JSON, единственный Content-Length, предел тела |
| Неограниченное количество HTTP-потоков и запросов | До 32 обработчиков, тайм-аут сокета, ограниченный limiter по клиенту и общий лимит |
| Известные уязвимости PyJWT 2.10.1 | Обновление PyJWT до 2.15.1 и повторная проверка зависимостей |
| Поддельные JWT с разными `kid` могли провоцировать загрузку JWKS | Проверка заголовка и длины токена, кеш ключей и ограничение обновления |
| TLS Postgres шифровал трафик без строгой проверки сервера | `verify-full` с доверенными CA certifi для пула и миграций |
| Контакты из текста передавались AI без маскирования | Найденные email, телефоны и Telegram-контакты маскируются; исходник сохраняется внутри системы |
| `get_lead` читал всю базу клиентов | Ограниченные запросы по ID и согласованный снимок для состояния |
| Постоянная загрузка полного состояния и лишнего auth-кода | ETag/304 после авторизации, адаптивный polling, пауза скрытой вкладки, кеш статики; auth-бандл исключён из публичного демо |
| Документация и интерфейс описывали прежнюю интеграцию | Переработан раздел «Как это работает», уточнены реальные каналы и смысл подтверждения отправки |
| WOV обещал безусловные сроки, цены конкурентов и свойства любого результата | Оценка по согласованному объёму, реальные этапы и критерии проверки; README соответствует HTML/CSS/JS |

## Правила счётчиков

Каждое обращение относится ровно к одной группе:

- **Проверить**: queued, processing, ready, needs_info, retry или failed.
- **Отправка**: сначала неопределённые результаты и отказы, затем остальные по возрасту. Согласовано, но Google ещё не подтвердил отправку. Сюда входят отказ, неопределённый результат и письмо в очереди.
- **Отправлено**: Google подтвердил вызов отправки. Это не подтверждение получения или прочтения.
- **Повтор**: точный повтор обращения, без второй сделки.

`Всего = Проверить + Отправка + Отправлено + Повторы`.
Число у навигации «Заявки» — проверка плюс отправка. Поиск влияет на показанные карточки; общая сводка и числа вкладок остаются глобальными. Публичное демо не отправляет письма и называет согласованные ответы «Согласованы».

## Проверка

Команды: `npm run build`, `python -m unittest discover -s tests`, `node tools/test_mail_script.mjs`, `python tools/test_live_neon.py`. HTTP-тестам нужен доступ к loopback; sandbox без него возвращает WinError 10013, что не является результатом работы API.

Регрессия покрывает все стадии очереди и формулу счётчиков, дедлайн до отправки, конфликт редактирования, неизменность одобренного письма, повторы и квоты, обязательный Origin, ошибочные тела HTTP, заголовки безопасности, закрытые файлы, авторизацию до 304, маскирование контактов и JWKS-кеш. Почтовый скрипт проверяется отдельно на HMAC, срок запроса, одного получателя, конфликты ID и отсутствие повторной отправки при неопределённости.

Тест Neon выполняется только на выделенной ветке `dev-briefops`: настоящие миграции, TLS с проверкой сертификата, приём, согласование, тестовый адаптер отправки и повторное открытие базы. Настоящих писем этот тест не отправляет. Интерфейс проверяется на обычном экране и ширине 390 px с вымышленными данными, изолированной SQLite и тестовым почтовым адаптером.

## Оставшиеся ограничения и следующие шаги

1. **Доступность.** Бесплатный Render засыпает; обработка фоновой очереди и напоминаний продолжится после пробуждения. Для гарантированного времени ответа нужен постоянно работающий процесс и внешнее наблюдение за доступностью. Платный тариф автоматически не включается.
2. **Публичная форма.** Origin, CORS, ID формы, ловушка и квоты снижают нежелательные запросы, но не доказывают, что запрос отправлен человеком с сайта: небраузерный клиент может подставить метаданные. При спаме следующий шаг — challenge-проверка на сервере. Обычная почта Gmail при этом не читается и в систему не импортируется.
3. **Почта.** Действуют квоты Google MailApp. Журнал идемпотентности Apps Script требует контроля объёма. При неопределённом результате нужна ручная проверка в Gmail; автоматическая повторная отправка остановлена. Входящие ответы пока видны только в Gmail.
4. **Масштаб.** Состояние по-прежнему содержит полную историю, хотя повторно скачивается только после изменений. При росте числа заявок нужны пагинация, отдельная лента событий и политика хранения. Ограничитель запросов локален экземпляру, доверие к X-Forwarded-For ограничено документированным proxy Render; при смене хостинга это надо пересмотреть.
5. **Доступ и данные.** Рабочая область рассчитана на одного владельца. Роли команды, процедуры удаления/экспорта данных, проверка резервного восстановления и юридические документы обработки данных требуют отдельной настройки. Маскирование контактов не делает произвольное описание полностью анонимным.
6. **Инфраструктура.** Проверка приложения не подтверждает настройки всех аккаунтов, MFA, сроков ключей и резервных копий. Секреты исключены из текущих отслеживаемых файлов; это не полный исторический поиск утечек во всех аккаунтах. GitHub Pages не позволяет задать произвольные HTTP-заголовки: frame-ancestors нельзя обеспечить через meta. BriefOps отдаёт защиту от встраивания заголовком.
