# Заявки сайта и ответы по email

## Два пространства

- `/` — публичная демонстрация с вымышленными данными.
- `/login` → `/workspace` — рабочая область World of Vibecraft. Доступ разрешён только владельцу с подтверждённым email в Neon Auth. Вход — по коду из письма.

Рабочие заявки хранятся в отдельной базе `briefops_live`. Публичные API состояния и CSV используют только демонстрационную базу. Включение рабочего режима без настроенного входа блокируется; использование одной базы для обоих пространств запрещено.

## Прямой приём с сайта

```text
Форма World of Vibecraft → BriefOps → сохранение заявки и уведомления в одной транзакции
                                      ├→ Google MailApp → email владельцу
                                      └→ очередь → разбор → проверка → подтверждённый email клиенту
```

`POST /api/integrations/wov` принимает JSON с `form_data`:

```json
{
  "form_data": {
    "form_id": "wov-v1",
    "site_url": "https://rinpocheshka.github.io/wov/",
    "submission_id": "unique-browser-submission-id",
    "name": "Клиент",
    "contact": "client@example.com",
    "idea": "Описание задачи"
  }
}
```

Поля проверяются на сервере. Контакт передаётся отдельно от описания: случайный адрес внутри сообщения не заменит контакт из формы. Повтор с тем же ID не создаёт вторую заявку; изменение данных с прежним ID возвращает конфликт.

Это публичный приёмник формы с ограничением частоты и дневного количества запросов. `form_id` и URL сайта являются метаданными, а не секретами или криптографическим доказательством источника. Код формы не содержит токенов BriefOps. Сервис не подключается к почтовому ящику, не читает Gmail и не импортирует обычные письма. Браузер получает подтверждение после сохранения заявки; неуспешный запрос можно повторить с прежним ID. CORS разрешает запросы только с origin сайта. Email-уведомление владельцу хранится в постоянной очереди и отправляется после сохранения заявки. Доступность приложения и очередь доставки следует контролировать отдельно.

## Отправка ответа

Менеджер проверяет адрес и текст, согласует ответ, затем нажимает **«Отправить по email»**. Согласование само по себе не запускает доставку. На Telegram и телефон письмо отправить нельзя.

В транзакции сохраняется отдельная отправка с неизменяемыми получателем, темой, текстом и ID. Фоновый обработчик передаёт её Google Apps Script по HTTPS с HMAC-SHA256 и временем подписи. Секрет хранится в переменных сервера и Script Properties, отсутствует в форме и репозитории.

Скрипт `integrations/google-mail/Code.gs` использует `MailApp`, а манифест запрашивает только `script.send_mail`. `GmailApp`, IMAP, POP и операции чтения почты не используются. Скрипт разворачивается от имени владельца отправляющего Google-аккаунта. Внешний URL разрешает серверные вызовы, но каждое сообщение требует правильной подписи. Получатель — один email; CC/BCC и произвольные заголовки не поддерживаются.

Постоянный журнал в Script Properties и блокировка защищают от повторов: тот же ID возвращает прежний результат. Если выполнение оборвалось после начала внешней отправки, статус становится неопределённым; автоматическое повторное письмо не отправляется. Проверка доставки в таком случае требует участия владельца. Журнал занимает квоту Script Properties и требует обслуживания при больших объёмах.

**«Отправлено» означает, что Google принял вызов отправки.** Это не подтверждение прочтения или получения адресатом. Ответ клиента на письмо поступает в Gmail; обратная синхронизация переписки в BriefOps пока не подключена.

## Переменные среды

| Переменная | Назначение |
| --- | --- |
| `BRIEFOPS_LIVE_DATABASE_URL` | Пул соединений отдельной рабочей базы |
| `BRIEFOPS_LIVE_DATABASE_URL_UNPOOLED` | Прямое соединение для миграций |
| `NEON_AUTH_BASE_URL`, `NEON_AUTH_JWKS_URL` | Управляемый вход и проверка подписей Neon |
| `BRIEFOPS_OWNER_EMAIL` | Единственный разрешённый владелец |
| `BRIEFOPS_MAIL_BRIDGE_URL` | HTTPS URL развёртывания Apps Script, оканчивается на `/exec` |
| `BRIEFOPS_MAIL_BRIDGE_SECRET` | Секрет HMAC, минимум 32 символа; тот же ключ в Script Properties |

Без настроенного почтового сервиса отправка недоступна, но согласованный ответ сохраняется. Публичный стенд не получает возможности отправлять письма.

## Проверка

```bash
npm run build
python -m unittest discover -s tests -v
node tools/test_mail_script.mjs
```

`tools/test_live_neon.py` проверяет миграции, повтор формы, структурированный контакт, согласование, одну отправку и сохранение после перезапуска на выделенной ветке `dev-briefops`, с тестовым почтовым адаптером. Настоящие письма этот тест не отправляет. Подключённый сервис дополнительно проверяется одной явно обозначенной тестовой заявкой и письмом на адрес владельца.

## Уточнения выпуска 1.3

- Для JSON и нативной формы обязателен Origin `https://rinpocheshka.github.io`. Публичные метаданные формы не являются секретом или доказательством происхождения небраузерного запроса.
- Контакт обязателен: email либо Telegram. Пустой контакт, неверные типы, превышения длины и заполненная ловушка отклоняются. Исходное описание сохраняется без удаления знаков или фрагментов кода.
- Повтор с тем же ID не расходует бизнес-квоту. Квоты и сохранение выполняются атомарно. После сетевого сбоя форма сохраняет поля и ID; нативная отправка получает HTML-подтверждение.
- Рабочие группы: проверка, отправка, отправлено и повторы. До подтверждения Google письмо остаётся в отправке, включая отказ и неопределённый результат. Отсчёт внутреннего времени ответа завершается после подтверждения отправки.
- До постановки письма в очередь согласованный текст можно вернуть в черновик. После постановки снимок получателя и текста неизменяем. Отказ можно повторить с прежним ID. При неопределённости автоматический повтор остановлен; требуется проверить Gmail.
- Уведомление владельцу имеет независимый статус и ручной повтор подтверждённого отказа. Отправка клиента не ждёт AI-обработки других заявок.
- Состояние выдаётся согласованным снимком, 304 разрешён только после проверки входа. Найденные контакты маскируются перед передачей в AI; произвольный текст не считается полностью анонимным.
